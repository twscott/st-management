# 数据库切换功能 - 使用说明

**创建日期**: 2026-02-24  
**功能**: 在运行时切换 sst (生产) 和 sstv2 (开发测试) 数据库

---

## 🎯 功能概述

### 实现的需求
1. ✅ 在菜单增加数据库切换功能
2. ✅ 醒目地显示当前使用的数据库
3. ✅ 防止误操作生产数据库

### 安全保护机制
- 🔴 **生产环境 (sst)**: 红色横幅 + 脉冲动画 + 二次确认
- 🟢 **开发测试 (sstv2)**: 绿色横幅
- ⚠️ 切换前显示确认对话框
- 🔄 切换后自动重启应用


- 后端执行 `Environment.Exit(0)`
- 您需要重新运行 `start-server.ps1` 或 `start-all-apps.ps1`
- 前端自动刷新页面

## 🔧 技术实现

### 后端 API 端点

#### 1. 获取当前数据库
```http
GET /api/database/current-connection
```

**响应示例：**
```json
{
  "databaseName": "sstv2",
  "isProduction": false,
  "connectionString": "Server=127.0.0.1;Port=3306;Database=sstv2;User=root;Password=***"
}
```

#### 2. 切换数据库
```http
POST /api/database/switch-connection
Content-Type: application/json

{
  "databaseName": "sst"
}
```

**响应示例：**
```json
{
  "success": true,
  "message": "Database switched to sst. Application will restart in 1 second.",
  "previousDatabase": "sstv2",
  "newDatabase": "sst"
}
```

### 技术细节

#### 1. 配置文件修改
切换数据库时，后端会修改 `appsettings.json`：
```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=127.0.0.1;Port=3306;Database=sstv2;..."
                                                           ^^^^^^
                                                           自动替换
  }
}
```

#### 2. 应用重启
- 使用 `Environment.Exit(0)` 优雅退出
- 延迟 1 秒让响应返回给前端
- 需要手动重新启动应用

#### 3. 前端刷新
- 切换成功后等待 2 秒
- 自动执行 `location.reload()`
- 重新连接到新数据库

## 🐛 常见问题

### Q1: 切换后页面无法刷新
**原因**: 应用重启耗时较长  
**解决**: 等待 5-10 秒后手动刷新浏览器

### Q2: 切换失败但应用已退出
**原因**: 配置文件更新成功，但应用已重启  
**解决**: 重新运行启动脚本即可

### Q3: 颜色横幅不显示
**原因**: CSS 未加载或浏览器缓存  
**解决**: 强制刷新浏览器 (Ctrl+Shift+R)

### Q4: API 调用失败
**原因**: 后端未启动或端口错误  
**解决**: 确认后端运行在 `http://localhost:5008`
